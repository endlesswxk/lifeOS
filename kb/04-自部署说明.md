# 自部署说明

把这套知识库放到网上，让别人也能用。按需要选一档，**A 档不需要任何账号**。

| 档位 | 谁能访问 | 需要什么 | 耗时 | 适合 |
|---|---|---|---|---|
| **A 只自己用** | 你自己 | 无 | 0 分钟 | 先看看是什么东西 |
| **B 局域网/团队内** | 同一网段的人 | Python | 2 分钟 | 给家里人、同事 |
| **C 公网** | 所有人 | GitHub / Cloudflare / Netlify 账号 | 10 分钟 | 真正做到"给所有人做的" |

## A 档：只自己用（双击即开）

`site/index.html` 是单文件应用，**双击就在浏览器里跑**，不联网、不需要服务器。

1. 把 `site/index.html` 拷到桌面或手机
2. 双击 / 用浏览器打开
3. 完成

想放到手机上：微信「文件传输助手」发给自己 → 点开 → 右上角「用其他应用打开」→ 选浏览器。

> 注意：不要在微信内置浏览器里长期使用，它可能限制本地文件的脚本执行。用 Chrome / Safari / Edge 打开。

## B 档：局域网内共享（2 分钟）

在放包的目录里起一个静态服务器：

```powershell
cd E:\SLACK-AI\个人健康知识库成果\site
python -m http.server 8000
# 或者指定监听所有网卡（手机要访问时用这个）
python -m http.server 8000 --bind 0.0.0.0
```

- 本机访问：`http://127.0.0.1:8000/`
- 手机访问：`http://<你的电脑局域网 IP>:8000/`（用 `ipconfig` 查 IPv4 地址，比如 `192.168.1.23`）
- 第一次连不上，多半是 Windows 防火墙拦了：允许 Python 的专用网络访问，或临时关掉防火墙测试

> 这个服务器只在你按 Ctrl+C 之前活着，且只在局域网内可见。**不要把它暴露到公网**——没有认证、没有 TLS。

## C 档：公网（选一个）

### C1 GitHub Pages（推荐，免费、稳定、和你已有的仓库一致）

**准备**：`site/` 目录下已经生成好 `index.html` 和 `.nojekyll`（`.nojekyll` 是必须的，否则 GitHub 会用 Jekyll 处理，中文路径和以 `_` 开头的文件会 404）。

**步骤**：

1. GitHub 新建仓库，例如 `health-kb`，**Public**（Pages 免费版要求公开仓库）
2. 把 `site/` 里的 `index.html` 和 `.nojekyll` 上传到仓库**根目录**
   - 网页上传：仓库页 → `Add file` → `Upload files` → 拖进去 → Commit
   - 命令行：见下方「附录：命令行推上去」
3. 仓库 → `Settings` → 左侧 `Pages`
4. `Source` 选 **Deploy from a branch**，分支选 `main`，目录选 **`/ (root)`**，Save
5. 等 1–3 分钟，地址是：

```
https://<你的用户名>.github.io/<仓库名>/
```

**常见坑**（都是真踩过的）：

| 现象 | 原因 | 处理 |
|---|---|---|
| 404 | 仓库名大小写写错 | 路径**区分大小写**，`health-kb` 和 `Health-KB` 是两个地址 |
| 404 | Pages 还没构建完 | 看 `Actions` 里 pages build 的状态，绿色再访问 |
| 页面空白 | 少了 `.nojekyll` | 补上传（内容为空文件即可） |
| 改了文件没变化 | 浏览器缓存 | `Ctrl+F5` 强刷，或换隐私窗口 |
| 打开是 README 不是应用 | `index.html` 不在根目录 | 检查路径层级，必须与 `/ (root)` 对应 |

> 如果你同时想公开**整套知识库**（Markdown + 引用 + 数据），可以整包上传，然后把 `site/index.html` 的内容
> 改名放到根目录的 `index.html`，或者用仓库 Settings → Pages 指向 `site/` 目录（目录选 `/docs` 时需把文件夹改名）。
> 最简单可靠的做法：**仓库根目录 = 本包结构，另在根目录放一份 `index.html` 指向 `site/`。**

### C2 Cloudflare Pages（拖拽上传，最快）

1. 登录 Cloudflare → `Workers & Pages` → `Create` → `Pages` → `Upload assets`
2. 把 `site/` 整个文件夹拖进去 → Deploy
3. 得到 `https://<项目名>.pages.dev`

优点：不需要 Git、构建飞快、国内访问通常比 `github.io` 稳。缺点：要有 Cloudflare 账号。

### C3 Netlify Drop（无需账号即可试）

把 `site/` 文件夹拖到 Netlify 的 Drop 页面，立刻得到一个临时域名。适合给别人看一眼，不适合长期。

## 版本与缓存

- 页脚和 `cards.json` 的 `meta` 里都有 `version` 与 `built_at`，**改了内容就改 version**（如 `1.1`），方便别人确认自己看的是哪一版
- 静态托管没有 Service Worker，更新后浏览器可能还拿旧的：让对方 `Ctrl+F5`
- 若以后要加 PWA（可装到桌面），`sw.js` 的缓存名必须跟着 version 变，否则用户会卡在旧版本

## 公开之前必须做的三件事

1. **确认里面没有你的个人数据。** 本包内容全部来自公开知识库，不含体检结果、不含身份信息；但如果你在 `cards.json` 里加了自己的指标，公开前删掉。
2. **处理许可证与署名。** 见 `02-引用与来源.md` 第一节。要点：
   - HLB 是 CC BY 4.0 → **必须署名**，footer 已写，别删
   - HumanSystemOptimization **没有许可证** → 本包只做事实引用与改写；若权利人要求，删除来源标 `HSO` 的卡即可（`search.py` 里搜不到就搜 `HSO`）
   - **`原始资料/` 不要传到公开仓库**：那里存的是上游原文快照，已经写进 `.gitignore`。缺了它不影响任何人使用（检索站、知识库、一页纸都是完整成品），只影响"重新生成引用"这一步——别人需要时跑一句：

     ```powershell
     python 数据与脚本/fetch_sources.py     # 现取 15 份上游原文
     ```
3. **保留边界声明。** footer 里那两段（证据是人群关联 / 不能替代医生）不是免责话术，是这个包的性质，删了会误导人。
