# 持续更新

这个包不是一次性交付物：上游仓库会更新，你自己的判断也会变。这份文件说的是**怎么把改一次的成本压到一条命令**。

---

## 一、三种更新，对应三条命令

| 你想做的 | 命令 | 耗时 |
|---|---|---|
| **改内容**（加卡、改某条、调证据） | 直接编辑 `数据与脚本/cards.json`，然后 `python 数据与脚本/deploy.py --push` | 1 分钟 |
| **改清单（会同时改 app）** | 编辑 `数据与脚本/checklist.json`（每条有 `id` 和 `card`），`deploy.py` 会重生成 app 的清单 | 1 分钟 |
| **只同步到 lifeOS 的 kb/** | `python 数据与脚本/deploy.py --sync-lifeos` | 1 分钟 |
| **看上游有没有更新**（HowToLiveBetter / HowToLiveLonger 出新条目） | `python 数据与脚本/deploy.py --upstream` | 30 秒 |
| **发新版本**（要让别人知道你更新了） | `python 数据与脚本/deploy.py --version 1.3 --push` | 1 分钟 |

`deploy.py` 干的事，按顺序：

```
重建 知识库/ + site/index.html + 02-引用与来源.md
  ↓
跑 15 项自检（不过就中止，绝不推没校验的内容）
  ↓
git commit（没有变化就干净退出，不产生空提交）
  ↓
git push + 打 tag v<版本>（加 --push 才做）
  ↓
线上校验：HTTP 200、内嵌数据块在、页面里已经是新版本号
```

推送后 **GitHub Actions 会再跑一遍**（`.github/workflows/selfcheck.yml`）：现取上游原文 → 重建 → 校验派生物与仓库一致 → 站点自包含检查。CI 红通常意味着「你手改了产物但没重建」，或者「忘了 `build_refs.py`」。

## 二、token：存一次，`deploy.py` 自己取

`deploy.py` 推送时的顺序：

1. 先试 `git push origin HEAD:main`（你机器上配了凭据助手就直接成功）；
2. 失败了就**从本机凭据库取 token** 再推，token 只在内存里拼进 URL，用完即弃；
3. 两样都没有才报错，并把「先存一次」的提示打出来。

token **不打印、不写进 `.git/config`、不落任何文件**。

### 存一次（本机凭据库，DPAPI 加密）

```powershell
$credman = "D:\DSH_HOME\skills\credential-manager\scripts\credman.ps1"

# 用文件传 secret：值不进命令行历史、不进脚本
$f = Join-Path $env:TEMP "gh-token.txt"
(Get-Clipboard).Trim() | Set-Content $f -NoNewline -Encoding ascii
& $credman set -Name github-lifeos -Url https://github.com/endlesswxk/lifeOS `
    -Username endlesswxk -AuthType bearer -SecretFile $f -Note "lifeOS 推送用"
Remove-Item $f

# 看有没有存上（只列条目，不打印值）
& $credman list
```

存好之后：`python 数据与脚本/deploy.py --sync-lifeos --push` 一条命令走完。

### 换机器 / 换仓库时

| 情况 | 做法 |
|---|---|
| 新机器上没有凭据库 | 用下面的方式 1 或 2 配一次 git 凭据助手即可 |
| 想换 token | 重新 `set` 同名条目覆盖；或用 `remove -Name github-lifeos` 删掉再 `set` |
| 临时用环境变量推一次 | `git push https://x-access-token:$env:GITHUB_TOKEN@github.com/...`（别写进文件） |

**方式 1：Git Credential Manager（Windows 自带）**

```powershell
git config --global credential.helper manager
git push -u origin main --tags   # 弹窗：用户名 endlesswxk，密码粘 token，之后不再问
```

**方式 2：GitHub CLI**

```powershell
winget install --id GitHub.cli
gh auth login          # 浏览器授权，不用手管 token
gh auth setup-git      # 让 git 走 gh 的凭据
```

> 共同点：**token 不进脚本、不进仓库、不进 `.gitignore` 之外的文件**。
> 别用「把 token 拼进 remote URL」的做法 —— 那会明文写进 `.git/config`。

**token 需要的最小权限**：
- Fine-grained：`Contents: Read and write` + `Workflows: Read and write`
- Classic：`repo` + `workflow`（**少了 `workflow` 推不动 `.github/workflows/`**）

**这个仓库的远端**：`https://github.com/endlesswxk/lifeOS`（知识库在它的 `kb/` 目录下）。

## 三、上游更新了怎么办

```powershell
python 数据与脚本/deploy.py --upstream
```

它会重新抓 15 份上游原文（10 章 HLB 正文 + 4 份台账 + README），逐份比 sha256，报告变了哪些：

```
发现 2 个文件有变化：
  · HLB_book/29-遭遇重大打击之后.md  （44,031 → 46,120 B）
  · HowToLiveLonger_evidence.json  （221,134 → 224,801 B）
```

然后按影响面决定动作：

| 变了什么 | 该做什么 |
|---|---|
| 只是文字修订、效应量没变 | 跑一次 `deploy.py` 重建引用即可，卡片不用改 |
| 效应量或分级变了 | 改对应卡的 `evidence` / `grade`，在 `CHANGELOG.md` 里记一行 |
| 新增了条目 | 看 `02-引用与来源.md` 里对应章节的条目数是否变了，评估要不要补卡 |
| 章节结构调整（条目重新编号） | **必须**重跑 `build_refs.py` 并检查每张卡的条号是否还指向正确的条目 |

> 为什么原文不进仓库：一来上游原文有版权差异（HumanSystemOptimization 无许可证），
> 二来链快照必然过期。`原始资料/` 已在 `.gitignore` 里，`--upstream` 就是"现取"的入口。

## 四、版本号怎么定

`cards.json` 里的 `meta.version` 是**唯一版本源**，页脚、`02-引用与来源.md`、tag 都跟着它走。

| 改动 | 版本 |
|---|---|
| 加/删卡片、改结论、升级证据 | 次版本 +1（1.2 → 1.3） |
| 只改错别字、调措辞、补链接 | 修订号 +1（1.2 → 1.2.1） |
| 一页纸条目增减（影响打印） | 次版本 +1，并在 CHANGELOG 里单独写 |

`deploy.py --version 1.3` 会同时更新 `version` 和 `built_at`。

## 五、回滚

每次 `--push` 都会打 tag，所以回滚是两条命令的事：

```powershell
git tag                                # 看有哪些版本
git checkout v1.2 -- 数据与脚本/cards.json     # 只回滚内容
python 数据与脚本/deploy.py --push              # 重建并推回去（会自动提交）
```

要整个仓库回到某版：`git revert <commit>` 后正常跑 `deploy.py`。**别用 `git push --force`**——Pages 和已安装的客户端缓存会乱。
