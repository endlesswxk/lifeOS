# 发布到 GitHub 的三种路径

包已经准备好了（15 项自检通过）。这里给三条路径，按「省事 × 零风险」排序。
**注意：三条路径里只有第三条需要 token，前两条不需要。**

---

## 路径 A（推荐）：新建独立仓库 `health-kb`

**为什么推荐**：`lifeOS` 仓库里有 Service Worker，把知识库挂在它下面会踩缓存坑（见文末）。
独立仓库零风险，而且两边的更新节奏互不干扰。

### 步骤（全程网页，2 分钟，不需要 token）

1. 打开 <https://github.com/new>
2. `Repository name` 填 **`health-kb`**，选 **Public**，**不要**勾 "Add a README file"，点 `Create repository`
3. 进仓库 → `Add file` → `Upload files`
4. 把这两个文件拖进去（都在 `site/` 里）：
   - `site/index.html`
   - `site/.nojekyll`（这是个空文件，**必须传**，否则 GitHub 用 Jekyll 处理会 404）
5. 点 `Commit changes`
6. 仓库 → `Settings` → 左侧 `Pages` → `Source` 选 **Deploy from a branch** →
   分支 `main`、目录 **`/ (root)`** → `Save`
7. 等 1–3 分钟，地址：

```
https://endlesswxk.github.io/health-kb/
```

### 想连文档一起公开？

再传这几个文件（都在包根目录）：`README.md`、`02-引用与来源.md`、`03-使用说明.md`、
`04-自部署说明.md`、`LICENSE`、`LICENSE-内容-CC-BY-4.0.md`、`CHANGELOG.md`。
**不要传 `原始资料/`**（上游原文，其中 HumanSystemOptimization 无许可证）。

如果要公开整包内容（`知识库/`、`一页纸清单/`、`数据与脚本/`），用命令行推更省事，见路径 C。

## 路径 B：放进现有的 `lifeOS` 仓库（`/kb/` 子路径）

**必须先替换 `sw.js`**，否则访问一次 `/lifeOS/kb/` 之后，手机断网打开生活系统会显示知识库页面。

### 步骤

1. 打开 <https://github.com/endlesswxk/lifeOS>
2. `Add file` → `Create new file`，文件名填 **`kb/index.html`**（输入 `/` 会自动建目录）
   - 内容太多，网页编辑不便 → 改用 `Add file` → `Upload files`，先把 `kb/index.html` 拖进去
3. 再上传本目录的 **`sw.js`**（覆盖根目录那个），它做了三件事：
   - `CACHE` 从 `lifeos-v2` 升到 `lifeos-v3`（老客户端会拿到新版本）
   - 只有应用根路径的导航才回写 `./index.html` 缓存
   - `/kb/` 等子页面只走网络，不污染离线外壳
4. `Commit changes`
5. 地址：

```
https://endlesswxk.github.io/lifeOS/       ← 生活系统（不变）
https://endlesswxk.github.io/lifeOS/kb/    ← 知识库（新增）
```

### 上传后必做的一次验证

1. 手机 Chrome 打开 `/lifeOS/`，强刷一次（等 SW 升到 v3）
2. 打开 `/lifeOS/kb/`，能搜到卡片
3. **回 `/lifeOS/`，开飞行模式再打开** —— 应该还是生活系统，不是知识库
   （这一步就是验证缓存污染修好了）

如果第 3 步还是知识库，说明 SW 没更新：设置 → 应用 → Chrome → 存储 → 清除网站数据，再打开一次。

## 路径 C：命令行推（要 token，适合推整包）

### 需要的 token 与权限

| 类型 | 链接 | 勾什么 |
|---|---|---|
| **Fine-grained（推荐）** | <https://github.com/settings/personal-access-tokens/new> | `Repository access` → Only select repositories → 选 `health-kb` 或 `lifeOS`；`Permissions` → `Contents: Read and write`（新建仓库还需 `Administration: Read and write`）；有效期设 7 天 |
| Classic | <https://github.com/settings/tokens/new?scopes=repo&description=health-kb> | 勾 `repo` |

> ⚠️ **不要把 token 贴进聊天。** 上一轮那两枚 `ghp_...` 就是这样留在会话记录里的，
> 后来还得去 GitHub 侧吊销、清理本地凭据。token 一旦进入对话或文件，就等于泄露。
> 正确的用法见下面两种。

### 用法 1：你自己在终端跑（token 不经过我）

```powershell
cd E:\SLACK-AI\个人健康知识库成果      # 本地已经是 git 仓库，提交和 tag 都在
git remote add origin https://github.com/endlesswxk/health-kb.git
git push -u origin main --tags
# 提示用户名密码时：用户名填 endlesswxk，密码粘贴 token
```

推 `lifeOS` 的补充文件时，用同一个 token：

```powershell
cd E:\SLACK-AI\lifeOS-部署包
git clone https://github.com/endlesswxk/lifeOS.git _repo
Copy-Item sw.js .\_repo\sw.js -Force
New-Item -ItemType Directory -Force .\_repo\kb | Out-Null
Copy-Item kb\index.html .\_repo\kb\index.html -Force
cd _repo
git add sw.js kb/index.html
git commit -m "kb: 知识库挂到 /kb/ + sw 修缓存污染(v3)"
git push
```

### 用法 2：存进本机凭据库，由我调用（不打印）

本机有凭据管理（DPAPI 加密存在 `%USERPROFILE%\.agents\credentials\`）。
你说一句「把 token 存进凭据库」，我给一个不落地的输入方式；之后推送时我从凭据库取，
**不会把 token 写进任何文件或输出**。

## 附：为什么 `/kb/` 会踩坑（技术细节）

`lifeOS/sw.js`（v2）的导航分支：

```js
if (req.mode === 'navigate') {
  fetch(req).then(res => {
    const copy = res.clone();
    caches.open(CACHE).then(c => c.put('./index.html', copy));  // 任何导航都写外壳缓存
    return res;
  })
}
```

Service Worker 的 scope 是 `/lifeOS/`，覆盖所有子路径。所以访问 `/lifeOS/kb/` 时，
知识库的 HTML 被写进了 `./index.html` 这个**应用外壳**的缓存位。
之后离线打开 `/lifeOS/`，`catch(() => caches.match('./index.html'))` 拿到的就是知识库页面。

v3 的修法：加 `isShellRequest()`，只有路径等于 scope 根（或根 + `index.html`）时才回写。
`/kb/` 的导航只走网络，离线时不影响应用。
